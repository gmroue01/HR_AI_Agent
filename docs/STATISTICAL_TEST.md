This document gathers the test function documentation for the statistical-testing suite in [`evals/shared/test_mcnemar_expense_eligibility.py`](../evals/shared/test_mcnemar_expense_eligibility.py).

[`METAMORPHIC_TEST.md`](./METAMORPHIC_TEST.md)'s suite checks a metamorphic relation (rewording shouldn't change the tools called) on a single pair per case — one original run, one paraphrase run, exact equality. That's a strong claim from a weak amount of evidence : a single Groq call is one draw from the model's sampling distribution, so a single pair matching (or not) could easily be noise rather than a real property of the model. This suite asks the same underlying question — does paraphrasing affect correctness? — but answers it with a statistical test over repeated sampling instead of a single exact-match assertion, which is what "statistical testing" adds on top of the metamorphic relation : a p-value quantifying how likely the observed disagreement is to be chance.

**Why McNemar's test.** McNemar's test is built for exactly this shape of data : two conditions evaluated on the same paired items, each outcome binary (correct/incorrect here). It asks whether *disagreements* between the two conditions are systematically skewed toward one condition, ignoring the pairs where both conditions agree (either both correct or both incorrect) — those carry no information about whether paraphrasing itself has an effect. Concretely, from the 2x2 table of (original correct/incorrect) x (paraphrase correct/incorrect), only the two discordant cells matter : *original-only-correct* (`b`) and *paraphrase-only-correct* (`c`). Under the null hypothesis that paraphrasing has no systematic effect, a disagreement is equally likely to go either way, i.e. `b` follows a `Binomial(n=b+c, p=0.5)`. McNemar's **exact** test (as opposed to its chi-square approximation, which needs a larger discordant count to be valid) is precisely a two-sided binomial test of `b` against that null — so this suite computes it directly with `scipy.stats.binomtest(b, b+c, 0.5)` rather than pulling in `statsmodels` for a wrapper around the same computation.

**Where the sample size comes from.** [`evals/shared/cases/expense_eligibility.py`](../evals/shared/cases/expense_eligibility.py) only has 3 cases, far too few discordant pairs to say anything statistically meaningful on their own. Rather than write more cases, each of the 3 cases is repeated `REPETITIONS = 10` times (30 paired trials total, 60 real Groq calls), re-sampling the same original/paraphrase pair repeatedly to capture the model's actual run-to-run variance rather than adding more distinct scenarios. This makes the test slow and non-free by construction — same trade-off as the rest of the real-API suites, just paid 20 times over (10 repetitions x 2 conditions per case) instead of once.

**Correctness criterion.** Same proxy as [`METAMORPHIC_TEST.md`](./METAMORPHIC_TEST.md) and the tool-correctness checks in [`OPIK_TEST.md`](./OPIK_TEST.md) : a run is "correct" if its `trace["tools_called"]` names exactly match the case's `expected_tools` — no LLM judge involved, so the statistical test measures variance in tool-call behavior, not variance in an LLM-as-a-judge's opinion of the reply.

## [`test_mcnemar_expense_eligibility.py`](../evals/shared/test_mcnemar_expense_eligibility.py)

**Objective** : Verify that paraphrasing an expense request does not have a statistically significant effect on whether the agent calls the correct tools, across repeated sampling of every case in `EXPENSE_ELIGIBILITY_CASES`.

- **`test_paraphrase_has_no_significant_effect_on_correctness`** — runs each case's original input and its paraphrase `REPETITIONS` (10) times each, classifies every run as correct/incorrect against `expected_tools`, and tallies the four cells of the paired contingency table (`both_correct`, `original_only`, `paraphrase_only`, `both_wrong`). Runs McNemar's exact test on the two discordant cells and asserts `p_value > ALPHA` (0.05) — i.e. fails to reject the null hypothesis that paraphrasing has no systematic effect. If no discordant pairs occur at all (both conditions always agreed), the test is skipped rather than trivially passed, since McNemar's test is undefined with zero disagreement to measure.

**Observed result** : a real run (30 paired trials, 60 Groq calls, ~9m30s) came back with zero discordant pairs — original and paraphrase agreed (correct or incorrect together) on every single trial, so the test skipped rather than computing a p-value. That is itself informative : it says the model's tool-call decision on these three cases is highly stable under rewording, stable enough that 30 repetitions never once caught it disagreeing with itself. It also means this particular dataset hasn't yet produced a case for McNemar's test to actually rule on — a case where the two conditions sometimes disagree would be needed to see the test reject or fail to reject a real effect.

Run with `pytest evals/shared/test_mcnemar_expense_eligibility.py -v -s` (`-s` to see `print`/assertion detail; expect several minutes given 60 real API calls).
